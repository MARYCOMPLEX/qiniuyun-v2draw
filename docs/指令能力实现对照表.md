# 指令能力实现对照表

> 状态: 持续更新 · 最后更新: 2026-06-14
>
> 本文档记录 Voice Canvas 计划支持的全部 LLM 指令能力，标注每项的实际实现状态，
> 并对未完成部分说明原因和后续计划。

---

## 一、工具集总览

项目经过三次工具集架构演进：

| 阶段 | 工具命名空间 | 状态 | 说明 |
|------|-------------|------|------|
| 阶段 1 — 多模态画布 | `canvas.*` 19 + `platform.*` 8 | Schema 完成，部分实现 | 图像为主，矢量为辅 |
| 阶段 2 — DrawIO 集成 | `drawio.*` 3 工具 | **已废弃，仅遗留兼容** | mxCell XML 渲染 |
| 阶段 3 — SVG 原生（当前） | `diagram.*` 3 工具 | **当前主力** | LLM 直接输出 SVG |

| 工具 | 说明 | Schema | Dispatcher | Prompt | 测试 |

| `diagram.display` | 全图重画（完整 `<svg>` 标签） | ✅ | ✅ | ✅ | ✅ |

| `diagram.append` | 续传被截断的 SVG 片段 | ✅ | ✅ | ✅ | ✅ |

### 配套能力

| 能力 | 状态 | 说明 |
|------|------|------|
| SVG XSS 白名单过滤 | ✅ | `sanitizeSvg.ts` — DOMPurify 49 标签 + 65 属性白名单 |
| SVG 流式渐进渲染 | ✅ | `isSvgComplete()` — 等 `</svg>` 闭合再分发 |
| SVG 内 `<image>` 元素支持 | ✅ | 图像生成后自动包装为 `<image>` 注入 SVG |
| dark/light 主题 CSS 变量注入 | ✅ | `SvgRenderer.tsx` — `THEME_VARS_DARK` / `THEME_VARS_LIGHT` |
| SVG edit 增删改 regex 操作 | ✅ | `<g id="X">` 正则匹配替换，支持嵌套管 |

### 未完成 / 规划中 🔮

| 功能 | 优先级 | 未完成原因 | 后续计划 |
|------|--------|-----------|---------|
| SVG 节点拖拽编辑 | 低 | 用户当前不需要编辑器交互，只读渲染满足需求 | 如用户需要，可引入 React Flow 做双向 mxCell ↔ React Flow 适配 |
| 精确端口路由（exitX/exitY） | 低 | 节点中心连线对流程图/架构图视觉够用，端口路由算法复杂度高（mxgraph 的 edge routing 涉及 A* + 端口排序） | 仅当用户反馈连线不够精确时引入 |
| SVG 导出 PNG | 低 | 已从 DiagramContext 移除 `capturePng`，当前无消费者 | 需要时可用 `foreignObject` + Canvas 或 `html-to-image` |
| 贝塞尔曲线连线 | 低 | LLM 输出 `<path d="M... C...">` 即可，暂不需要 prompt 引导 | 加到 prompt 连线指南即可 |

### 未完成部分的总体说明

**核心理由**：项目经历了两次重大方向调整。

1. **第一次转向**（2026-06-13）：从纯矢量画布（几何 shape）转向多模态画布（图像 layer）。此时规划了 19 个完整的图像工具，但很快就面临第二次转向。

2. **第二次转向**（2026-06-14）：用户决定"默认矢量，图像作为素材拼到矢量图上"。引入 react-drawio 实现矢量 + 图像混合画布，随后又自研 SVG 引擎替代 iframe。在这个 SVG-first 的路线下，**大部分 `canvas.*` 图像工具的使用场景被压缩**——用户通过 `diagram.display` 直接让 LLM 画 SVG 矢量图，只在需要真实图像素材时才会用到 `canvas.generate_image` / `canvas.generate_character`。

因此，**19 个 canvas.* 工具中的 Schema + Dispatcher 层全部完成**（保证 LLM 调用时不会报错），但**后端图像处理 API 仅实现了基础文生图**。其余编辑/变换/去背景/超分等 API 属于"需要时再接通"的状态。

**当前实际可用路径**：
- 矢量图：`diagram.display` / `diagram.edit`（完整可用）
- 基础生图：`canvas.generate_image` → 自动包装为 `<image>` 注入 SVG
- 图层操作（移动/缩放/旋转/删除）：同步工具，完整可用
- 撤销/清空：完整可用

## 六、非工具类指令能力

### 已实现 ✅

| 能力 | 说明 |
|------|------|
| 多轮对话上下文 | 最近 5 轮 narration 注入 LLM，支持指代消解（"刚才那个"） |
| 复合指令拆解 | LLM 一条 response 最多返回 8 条 commands，前端逐条分发 |
| 决策树引导 | directorPrompt 内置 8 分支决策树，按序匹配用户意图 |
| 用户指令无法解析时的降级 | 输出单矩形 + narration 说明，不崩溃 |
| 流式 SVG 渐进渲染 | `isSvgComplete` 检查 `</svg>` 闭合，支持 display + append 续传 |
| streamText 退化为 prompt（无 history 时） | `route.ts` 兼容旧行为，无 history 时不发 messages |

### 未完成 🔮

| 能力 | 优先级 | 未完成原因 | 后续计划 |
|------|--------|-----------|---------|
| Web 搜索集成 | 中 | `src/shared/providers/search/` 目录已创建，provider 注册机制已备，但未接入具体搜索引擎 | 接入 Exa / Tavily 搜索 API，让 LLM 获取实时信息辅助画图 |
| 图片参考上传 | 低 | 用户上传图片作为生图参考图（img2img），前端/后端均未实现 | 按需实现 |
| 画布协作（多人） | 低 | 单人使用场景，无协作需求 | 暂不规划 |
| 离线数据流模拟器增强 | 低 | 当前模拟器仅演示三阶段管道，无 full tool chain 模拟 | 可用于 Demo 场景增强 |
